## 1. 摘要

本项目用卷积神经网络（CNN）识别 FER2013 数据集中的人脸 7 类表情（angry / disgust / fear / happy / sad / surprise / neutral），再根据预测出的 7 类情绪概率，从 **66 张**已标注情绪的猫 meme 表情包中检索最匹配的一张，并用 Streamlit 做成网页演示。
模型方面先自写了一个小 CNN（2.73M 参数，测试集 64.73%），之后**改用 ImageNet 预训练 ResNet18 微调 + TTA**（测试集 69.71%）；2026-10-31 **模型优化 v2** 又升级为 **efficientnet_b0@160 微调 + 3-seed 集成**（训练配方：AMP、Lion、EMA、mixup、强增强），测试集 **75.93% / Macro-F1 0.7443**。

主要结果：

| 指标 | 结果 |
|---|---|
| 测试集（PrivateTest，3589 张）Accuracy | **75.93%**（efficientnet_b0@160 × 3-seed 集成 + 6 视角 TTA；单模型 + TTA 约 74.3%） |
| 测试集 Macro-F1 | **0.7443** |
| 单类最好 / 最差 F1 | happy 0.9184 / sad 0.6363（disgust F1 0.7368，fear 0.6450；v1 时代分别为 0.8884 / 0.5224 / 0.6804） |
| 最终模型 | **efficientnet_b0@160（10.7M 参数）微调 30 轮**，3 个随机种子（42/43/44）概率平均 + 6 视角 TTA；单模型训练约 60 分钟/个（本机 RTX 5060） |
| 对比（自写 CNN E8 → v1 → v2） | 64.73% → **69.71%**（ResNet18+TTA） → **75.93%**（effb0+集成+TTA），共 **+11.2 点** |
| 演示程序 | Streamlit 网页：上传/随机图 → 7 类概率条 → 选中 meme + 软匹配 Top-5；可切换模型（含 3-seed 集成）、软/硬匹配、TTA；另有可选"视觉多样性备选"与"神似模式" |

> **建议 2（视觉神似）审查结论（2026-10-31）**：CLIP 跨模态探针未通过（检索=随机水平、零样本标签更差），**不做 CLIP 视觉融合主匹配**；但 CLIP 文本属性画像与 478 点关键点几何有真信号，已落地为**可选"神似模式"**（默认关）：`F = (1-β)·情感分 + β·视觉分`，验证集上 β=0.1~0.6 时情绪命中率仅 -0.11pp、类内视觉分 0.685→0.728。详见 §6.6。

## 2. 问题定义

输入一张人脸图片，输出 7 类情绪概率，再输出一张"最符合这个情绪"的猫 meme。

```
输入图片 → 预处理（自写 CNN：48×48 灰度；ResNet：128×128 RGB） → CNN
        → 7 类概率 softmax（TTA 时对 6 个视角取平均） → meme 匹配策略 → 输出一张猫 meme
```

任务分两块：

1. **分类**：7 类表情分类，用 FER2013 官方划分训练/验证/测试；
2. **匹配**：情绪标签 → meme 选择，重点解决"预测不确定"和"某些类 meme 太少"两个问题。

## 4. 方法

### 4.1 预处理与数据增强

所有图片统一为 48×48 灰度，用训练集统计量归一化（mean=0.5077，std=0.2550）。训练时在线随机增强（只用 PIL，不用 torchvision）：

1. 随机水平翻转（p=0.5）；
2. 随机平移（四周 pad 4 后随机裁回 48×48）；
3. 随机旋转 ±10°；
4. 亮度随机 ±10%。

验证/测试集不做任何增强。

迁移学习模型的输入不同：48×48 先**一次性**放大到 128×128（预 resize，避免每个 epoch 重复缩放），
灰度复制成 3 通道，按 ImageNet 的 mean/std 归一化；增强在 128×128 上做，平移幅度按比例放大。预 resize 一次只需约 3.5 秒。

### 4.2 模型

**① 自写小 CNN（E1~E8 实验，`04_model.py`）**：最终选了 `flat` 档（3 个卷积块 + 展平分类头）：

```
Conv(1→64, 3×3) + BN + ReLU + MaxPool    48×48 → 24×24
Conv(64→128, 3×3) + BN + ReLU + MaxPool  24×24 → 12×12
Conv(128→256, 3×3) + BN + ReLU + MaxPool 12×12 → 6×6
Flatten(6×6×256 = 9216) → FC(9216→256) + ReLU + Dropout(0.4) → FC(256→7)
```

- 参数量 2,731,463；
- 与原始方案（`baseline`：32/64/128 通道 + GAP + FC(128→7)，93,799 参数）相比，flat 保留了空间位置信息、容量更大；
- 另有中间配置 `wide`（44 万参数，GAP + 隐藏层），见消融实验。

**② 最终采用的迁移学习模型（E9，`08_transfer_train.py`）**：ImageNet 预训练 **ResNet18**（timm `resnet18.a1_in1k`，**11,180,103 参数**）：

- 把 ImageNet 的 1000 类分类头换成 7 类（重新初始化），其余卷积/BN 权重**全部加载 ImageNet 预训练值**；
- 输入 128×128 RGB（FER 灰度放大 + 复制成 3 通道），ImageNet mean/std 归一化；
- 在 FER2013 上**全参数微调** 20 轮（12.5 分钟）。预训练特征 + 小数据微调，比从零训练明显更准。

### 4.3 训练设置

**自写 CNN（E8，`05_train.py`）**：

| 项 | 设置 |
|---|---|
| 损失 | CrossEntropyLoss + label smoothing 0.05 |
| 优化器 | Adam，lr=5e-4 |
| 学习率调度 | CosineAnnealingLR（T_max=80） |
| batch size | 128 |
| 最大轮数 / 早停 | 80 epoch / 验证集准确率连续 12 轮不升则停（实际第 74 轮停，最优在第 62 轮） |
| 随机种子 | 42（固定种子，可复现） |
| 训练耗时 | 74 轮 × 约 11.0 秒 ≈ 13.6 分钟（GPU） |

**最终模型：ResNet18 迁移学习（E9，`08_transfer_train.py`）**：

| 项 | 设置 |
|---|---|
| 损失 | CrossEntropyLoss + label smoothing 0.05（不加类别权重，优先整体准确率） |
| 优化器 | AdamW，lr=3e-4，weight_decay=1e-4 |
| 学习率调度 | CosineAnnealingLR（T_max=20） |
| batch size | 64 |
| 最大轮数 / 早停 | 20 epoch / patience=5（实际跑满，最优第 16 轮） |
| 输入 | 128×128 RGB（ImageNet 归一化） |
| 训练耗时 | 20 轮 × 约 37.6 秒 ≈ **12.5 分钟**（GPU） |

**TTA（方案 B，推理端）**：对原图、水平翻转、上下左右平移（幅度 = 输入边长/24）共 6 个视角分别算 softmax，再取平均。
不训练、不增加模型参数；实测自写 CNN +0.78 点、ResNet18 +1.25 点。

**模型优化 v2（2026-10-31，最终采用）**：**efficientnet_b0@160** 微调，训练配方 = AMP fp16 + **Lion**（lr1e-4）+ label smoothing 0.1 + **mixup 0.2** + **强增强**（旋转±15°/缩放/平移/亮度对比度/随机擦除）+ **EMA 0.999** + warmup 2 + grad-clip 1.0 + 类别权重，batch 64，30 epoch（patience 10）；推理端用 **6 视角 TTA**，再把 **3 个随机种子（42/43/44）的概率平均**。完整消融/对比/测试结果见 §5.5。

## 5. 实验与结果

### 5.1 消融实验（测试集 3589 张，只用于最终比较）

| 实验 | 模型档位 | 关键设置 | val Acc | test Acc | test Macro-F1 |
|---|---|---|---|---|---|
| E1 | baseline | 加权 CE，patience=3 | 50.18% | 51.24% | 0.4447 |
| E2 | baseline | 不加权，patience=3 | 47.37% | 48.01% | 0.4014 |
| E3 | baseline | 加权，patience=8 | 52.66% | 52.61% | 0.4675 |
| E4 | baseline | 不加权，patience=8 | 56.53% | 55.50% | 0.4560 |
| E5 | wide | 不加权，40 epoch | 59.63% | 59.29% | 0.4934 |
| E6 | wide | 加权，40 epoch | 54.61% | 55.64% | 0.4981 |
| E7 | flat | 不加权，60 epoch，lr=1e-3 | 59.29% | 59.99% | 0.4993 |
| E8 | flat | 不加权，80 epoch，lr=5e-4，label smoothing 0.05，加随机平移增强 | 62.97% | 64.73% | 0.5368 |
| E8 + TTA | flat | 对 E8 做 6 视角 TTA（推理端） | — | 65.51% | 0.5437 |
| **E9（最终模型）** | **resnet18 迁移学习** | **ImageNet 预训练，128×128 RGB，AdamW lr=3e-4，20 epoch，不加权，LS 0.05** | **67.51%** | **68.46%** | **0.6633** |
| **E9 + TTA（最终成绩）** | **resnet18 迁移学习** | **对 E9 做 6 视角 TTA（推理端）** | **68.01%** | **69.71%** | **0.6796** |

结论：

1. **baseline 明显欠拟合**（93,799 参数，训练集准确率也只到 ~53%）——参数量/容量是主要瓶颈，不是数据问题；
2. **早停 patience=3 太激进**：余弦学习率还在高位时就停了（E1/E2 只跑到 11~16 轮），改成 8~12 后正常；
3. **类别加权对整体准确率是负作用**（E6 比 E5 掉 3.65 个百分点），但能显著提升 disgust 召回（E6 的 disgust 召回 60%，不加权模型只有 0~3.6%）——这是"准确率 vs 小类召回"的取舍；
4. 降低学习率 + 标签平滑 + 更长时间训练 + 增加随机平移增强，把自写 CNN 的测试准确率从 59.99% 提到 **64.73%**；
5. **迁移学习是提升最大的一步**：ImageNet 预训练 ResNet18 微调把测试准确率从 64.73% 提到 **68.46%**，TTA 再 +1.25 点到 **69.71%**；
6. TTA 是"免费"的：不训练、不加参数，两个模型上都稳定 +0.8~1.25 个点。

|---|---|---|---|---|---|---|---|

| disgust | 12 | **33** | 2 | 2 | 2 | 3 | 1 |

主要错误（占该类样本比例）：

1. sad → neutral：106 张（17.8%）
2. neutral → sad：86 张（13.7%）
3. fear → sad：82 张（15.5%）
4. fear → angry：73 张（13.8%）
5. sad → fear：67 张（11.3%）

分析：

- **happy / surprise 仍然最好**（F1 0.89 / 0.81）：笑、张口瞪眼这类特征在 ImageNet 特征空间里很容易区分；
- **disgust 从"完全不会"变成"基本能认"**：召回 60%（33/55）、F1 0.68。这是迁移学习带来的最大改善——预训练特征让仅 436 张训练样本的小类也能学到东西；
- **fear 召回从 31% 提到 48.7%**，但仍有 13.8% 被认成 angry、15.5% 被认成 sad；
- **剩余主要混淆集中在 sad / neutral / fear 三类**：低分辨率灰度图上这三类的嘴部、眼神差别小，这与 FER2013 论文报告的人类混淆模式一致；
- 与 E8（自写 CNN）相比，错误从"整类放弃"变成"少量类别间混淆"，这是模型质量提升的直接体现。

### 5.5 模型优化 v2：训练配方 / backbone / 多 seed 集成（2026-10-31）

**动机**：v1（ResNet18@128 + 20 epoch + 基础增强）到 69.71% 后，误差集中在 sad/neutral/fear 三类；训练配方（无 warmup/EMA、增强偏弱、单 seed、fp32）和模型容量都有改进空间。本阶段**全程只用验证集（3589 张）选型**，测试集只在最后评估一次。

**① 训练配方消融（resnet18@128，30 epoch，AMP 混合精度）**

| 实验 | 配方 | val Acc | val Macro-F1 | 最优轮 | 耗时 |
|---|---|---|---|---|---|
| R1 | AdamW lr3e-4 + LS0.05 + 基础增强 + AMP | 68.35% | 0.6457 | 21 | 30.6min |
| R2 | R1 + EMA0.999 + SWA5 + warmup2 + grad-clip1.0 | 67.90% | 0.6546 | 16 | 29.9min |
| R3 | R2 + mixup0.2 + 强增强（旋转/缩放/平移/亮度对比度/随机擦除）+ LS0.1 | 69.10% | 0.6587 | 30 | 37.2min |
| **R4** | **R3 + Lion 优化器（lr1e-4）** | **69.96%** | **0.6722** | 23 | 35.0min |

## 6. meme 匹配策略

### 6.1 两种策略

1. **硬匹配（baseline）**：取概率最大的情绪 → 在该情绪候选图里随机挑一张。
   - 缺点：argmax 错就整体错；某类只有 1 张图时会反复同一张。
2. **软匹配（推荐）**：对每张 meme 计算

   score(meme) = Σ over 7 类 i：p_i × sim(情绪_i, meme 的情绪)

   其中 p_i 是模型给出的第 i 类概率，sim 是 7×7 情绪相似度矩阵（对角=1，例如 sad-neutral 0.6、fear-surprise 0.8）。取分数最高的 meme。
   - 优点：模型不确定时也能选出合理表情；某类缺图时相似类会自动补位（天然带回退）。
   - **2026-10-31 修复**：同一情绪所有 meme 的软匹配分数完全相同，旧实现 `sort_values` 取第一张 → 同一种情绪永远只显示同一张图（验证集 3589 次查询只用到 **7 张**）。现改为"选中情绪与旧逻辑完全一致 + 同类同分候选随机 + 避免连续重复"；实测 label_hit 0.6773、S 加权相似度 0.8124 均不变，用到的不同 meme **7 → 58 张**、连续重复 **636 → 0 次**。

**同分候选选择策略（2026-11-01 新增，页面可选）**

"同分随机 + 防连续重复"是演示层的多样性修复（不改变情绪判断、不改变任何准确率指标），但有三点要注意，因此把它做成页面可选项（默认仍是"随机+防连续重复"，原有行为不变）：

1. **统计上无偏**：同一情绪类内所有 meme 的软匹配分完全相同，模型无法区分谁更合适；均匀随机挑选是无偏的（期望指标不变，实测 label_hit 0.6773 / S 相似度 0.8124 完全一致）；
2. **"防连续重复"是 UI 启发式**：它让同一张图连点两次时换一张、观感更好，但也排除了上一张；随之而来的问题是**同一张图的结果不再确定**，做复现/答辩解释时不够直观（这点由"确定性"选项解决）；
3. **粒度局限**：随机策略把类内所有图等概率对待，无法体现"某张图更贴切"的人工偏好——这部分由可选的"神似模式"（视觉加权）弥补，而不是继续在随机策略上打补丁。

| 选项 | 行为 | 适用场景 |
|---|---|---|
| **随机 + 防连续重复（默认）** | 同类同分随机，尽量避开上一张 | 现场演示观感 |
| 纯随机（不防重复） | i.i.d. 均匀采样 | 需要无偏统计时 |
| 确定性（图片哈希） | 按输入图片内容哈希固定结果 | 可复现/可解释（同一张图每次同一张 meme，不同图分布均匀） |
| 固定第一张 | 修复前的旧行为 | 对照演示"旧 bug 只会出同一张" |

四种策略都只影响"同情绪类内挑哪张"，**不改变情绪类别判断与任何准确率指标**；`07_demo_app.py --selftest` 已新增 4 种策略验收（情绪一致 / 随机多样 / hash 确定 / first 固定），Streamlit AppTest 也已覆盖切换。代码位置：`07_demo_app.py` 的 `TIE_STRATEGIES` / `_pick_from_candidates()` / `pick_meme()`。

  - **备选范围**：仅同情绪类（默认）/ 同类为主（至少 1 张同类）/ 自由补充；
  - **视觉特征**：ImageNet ResNet18（默认，看外观差异）/ FER 微调 ResNet18（偏表情特征）；
  - **换一批**只换备选、主推固定；页面显示余弦距离（0=一样，越大越不同）。
- **选择算法**（`代码\11_visual_diversity.py`）：按范围构造候选池 → 贪心 max-min（备选1 离主推最远、备选2 到已选两张的最小距离最大），但距离限制在 **60%~95% 分位带**内——离线目检发现纯最大距离会选到"只有一团绒毛纹理"的怪图，分位带只损失约 0.02 多样性但备选明显更正常。
- **离线验证**（验证集 3589 张，3 范围 × 2 特征）：
  - 主推情绪与旧逻辑不一致：**0 条**（主推完全不变）；

  - 近重复对（两两距离 <0.05）：**0**；
  - 换一批：同类为主/自由补充平均 **5.5~5.9 个不同组合**（上限 6），仅同类约 4 个（受类大小限制，属预期）。
- **验收**：`--selftest` 20 图 × 3 范围 × 2 特征 = **120 次选择/换一批全部通过**；Streamlit AppTest 各开关/选项组合 `exception=[]`，渲染 4 图（输入+主推+2备选）+ 3 表。
- **影响**：模型权重/测试集指标完全不变；主推仍是唯一正式输出，2 张备选只作可选演示增强。

### 6.6 建议 2：视觉"神似"路线（CLIP 探针 + 关键点/属性加权，2026-10-31 落地）

**目标**：在情感主判据（软匹配）不变的前提下加一点"视觉神似"信号——不只要求 meme 情绪类别对，还希望神态（眼睛/嘴型/气质）更像。用户要求的形式是**加权求和**：
`F(meme) = (1-β) × 归一化情感分 + β × 视觉神似分`。

**B0 关键部位可行性预检（先验证"能不能提取"，再做）**：

| 侧 | 结论 |
|---|---|
| 人脸 | ✅ **mediapipe 1.2.0（478 点）可用**。opencv 5.0.0.93 有 abi3 轮子（修正此前"opencv 装不上"的判断，仅神似模式使用，主流程仍不依赖）；FER 48×48 放大后 14/14 张语义检查通过、10~12ms/张。另有 onnxruntime + ONNX 478 点备份（9ms/张，与官方 tflite 误差 0.0002px） |
| 猫 meme | ⚠️ **部分可行**。CatFLW 48 点 tflite（CC BY-NC 非商用）照片风可用，插画/像素风失败；58 张中仅 36 张两路裁剪一致（`tizee` 系列全部不可用）→ **猫侧关键点不接入交付**，改用"人工神态标签"（`数据\shensi_meme_tags.json`，58 张） |
| 几何判别力 | 仅用关键点几何分 7 类表情 = **28.6%**（随机 14.3%，happy 召回 53%）→ 关键点只作**辅助**，不替代 CNN |

**神似模式（已接入演示，默认关闭）**：
- 视觉分 = **0.50 × 神态属性画像 + 0.35 × 关键点几何 + 0.15 × CLIP 外观相似度**；
- 关键点几何：嘴开合度（上/下唇中点距 ÷ 脸宽）、眼睁开度（上下眼睑距 ÷ 眼宽）、嘴角上扬、眉眼距、头部倾斜，用验证集分位映射到 0~1 后，与 meme 人工神态标签（闭嘴/张嘴/张大嘴/吐舌、睁眼/瞪眼/眯眼/闭眼…）比"神态动作相似度"；mediapipe 在验证集 **3315/3589 = 92.4%** 检出人脸，未检出的样本几何项退化为中性（不影响主判据）；
- 关键点确实带神态信息（验证集逐类几何均值，mediapipe）：`surprise` 嘴开合 **0.357**、眼睁开 **0.447** 最高；`neutral` **0.085** / `sad` **0.102** 嘴开合最低；`happy` 嘴角上扬 **+0.002** 最高（笑）、`surprise` **-0.075** 最低（张嘴）；
- **β 扫描**（验证集 3589）：β=0 → 情绪命中 **0.6773**（= 历史 label_hit，完全一致）；β=0.1~0.6 → **0.6762~0.6768**（仅 -0.11 个百分点），类内平均视觉分 0.685 → **0.728**；用到 48/58 张 meme、最大单图占比 17.6%；默认 **β=0.35**，页面可调 0.10~0.60；

### 6.7 GIF 多帧视觉特征（B/C 方案，2026-11-01）

**动机**：数据管线为训练/匹配/特征一致，所有 meme 统一使用静态首帧 PNG；GIF 的动画信息此前只用于页面播放。B/C 让**可选视觉功能**（视觉多样性备选、神似模式）能用更代表整段动画的视觉特征，而**主匹配/情绪判断/准确率完全不变**（仍用人工标签 + 静态首帧分类）。

**做法**：
- 新增 `代码\17_meme_gif_frames.py`：对 18 张 GIF 均匀采样 ≤16 帧（共 **239 帧**；2026-11-02 扩库后为 **20 张 / 271 帧**）、按时长加权保存 `数据\meme_gif_frames\<stem>.npz`；用 ImageNet ResNet18 特征找"与首帧余弦距离最大的采样帧"作为**峰值帧**（`数据\meme_anim_peak\<stem>.png`，**20/20 的峰值都不是首帧**）；

**特征差异（ImageNet 特征，GIF 行，余弦）**：first↔mean 平均 **0.933**（B 较温和，短/静态 GIF 近似首帧）；first↔peak 平均 **0.793**（C 变化明显）；mean↔peak 0.925。明细 `_probe_clip\gif_visual_mode_diffs.csv`。

### 6.8 F 方案：匹配层温度缩放 / 情绪相似度矩阵调优（2026-11-02）

- **基线**：v2 单模型 + 6 视角 TTA 的软匹配 **label_hit = 0.7242**（注：历史文中的 0.6773 是 v1 模型的口径；v2 模型显著更高）。
- **温度缩放**（只改匹配用概率，不改分类 argmax）：`p = softmax(logits/T)`，在 val 上网格搜 T；**T*=0.65** 时 label_hit = **0.7292（+0.50pp）**，且 5 折 CV 同样 +0.50pp（稳健）；同时 ECE 从 0.094 降到 0.053（校准也更好）。
- **情绪相似度矩阵调优**：对 7×7 `EMOTION_SIM` 的 21 个非对角元素做坐标上升，**全量 val 上可到 0.7389（+1.47pp，乐观）**，但 **5 折 CV 只有 0.7269（+0.27pp）** → 明显在验证集上过拟合，**不推荐上线**。
- **结论**：只推荐**温度缩放**（T≈0.65）作为可选匹配策略；相似度矩阵保持原手工版本。若上线，应做成"概率温度校准"开关（默认关，保持原行为），并且只影响软匹配打分、页面展示的概率仍用原始值；参数只在 val 拟合，测试集不参与。详见 `结果\match_calibration_v2.md` / `.json`、脚本 `代码\20_match_calibration.py`。
- **落地（2026-11-02）**：演示页侧边栏已新增 **"概率温度校准（改善软匹配，val +0.5pp）"** 开关（默认关）；勾选后 `pick_meme` / `pick_meme_shensi` / Top-5 表使用校准概率，概率条与预测文字仍用原始概率；`--selftest` 验证温度缩放不改变 argmax、分组选择覆盖全部权重。

### 6.9 相似性匹配的边界：6 种匹配方式对比（val-only，2026-11-02）

**动机**：验证"利用情绪相似性扩大匹配范围是否能让匹配更精准"。结论是：**相似性软匹配早已是默认方案，但在严格 label_hit 上并不优于硬匹配**；它能改善的是"不确定时的合理性/观感"，不是精确命中率。

对比（v2 单模型 + 6 视角 TTA，val 3589 张，5 折 CV 选超参、测试集未参与）：

| 匹配方式 | 严格 label_hit（5 折 CV） | 软命中@0.6 | 软命中@0.7 |
|---|---|---|---|
| hard（argmax） | **0.7300 ± 0.0099** | 0.7999 | 0.7481 |
| soft（当前默认，手工 7×7 矩阵） | 0.7242 ± 0.0070 | 0.7994 | 0.7451 |
| soft + 温度 T=0.65 | 0.7292 ± 0.0070 | **0.8019** | 0.7484 |
| blend α（hard/soft 插值，CV 选 α） | 0.7289 ± 0.0080 | 0.7997 | 0.7470 |
| gated θ（高置信 hard/低置信 soft） | 0.7236 ± 0.0079 | 0.7994 | 0.7445 |
| conf_sim（混淆矩阵相似度向手工矩阵收缩） | 0.7300 ± 0.0082 | 0.8011 | 0.7484 |

**解读**：
- 严格指标上 **hard 最好（73.00%），任何"扩大相似范围"的变体都没有超过它**（soft 72.42、conf_sim 73.00 持平）；原因是严格命中要求"meme 情绪 == 真实情绪"，而相似加权会把部分样本从正确类"拉向"相似类；
- 混淆矩阵相似度在全量 val 上看似到 0.7303，但 5 折 CV 回落到 0.7300（与 hard 持平）→ 又是过拟合，和 §6.8 的矩阵调优结论一致；
- "软命中率"（相似类算半对）上差异也很小：soft+T 的 0.8019 略高于 hard 的 0.7999（+0.2pp），说明相似性的价值主要体现在"不确定样本的观感"而非指标；
- 因此**相似性匹配的合理定位是"提高不确定时的鲁棒性/可解释性"**，而不是"提高严格准确率"；若要继续提升严格指标，应回到分类模型本身（见 §8.2），而不是继续扩大匹配范围。

产物：`结果\match_variants.md` / `.json`、脚本 `代码\21_match_variants.py`。

### 6.10 多情绪（混淆性）meme 匹配实验（val-only，2026-11-02，负结论）

**动机**：互联网上不少 meme 天然可表达多重情绪（Smudge 猫 sad/neutral、side-eye 猫 disgust/angry 等）。如果给这些 meme 标"多标签分布 q"，让它们去匹配"模型本身也不确定"的照片，是否更合理？

**做法**：
- `数据\meme_emotion_multi.json`：对现有 66 张中 **26 张**人工标第二情绪（最多 2 个标签、权重 0.7/0.3 或 0.6/0.4、权重和=1；未标的一律 one-hot）；
- `07_demo_app.py` 新增可选 `multi_q` 参数（`soft_scores/pick_meme/top_meme_table/pick_meme_shensi` 支持 `p·SIM·q`），**默认 None = one-hot，行为逐位不变**；`22_multi_label_match.py` 做 val-only 对比。

**关键发现**：
1. **v1 的加权平均 `p·SIM·q` 在数学上永远打不过 one-hot**：任何分布 q 的加权平均 ≤ 其最大分量，多标签 meme 只会被"摊薄"，实测 `multi_rate=0`（一次都没被选中），**无任何效果**；
2. 换成能让多标签 meme 竞争的打分后（cosine / 取标签最大值 / 低置信才启用）：

| 方案 | strict | coverage | multi_rate |
|---|---|---|---|
| baseline（one-hot 软匹配） | **0.7242** | 0.7428 | 0.2705 |
| cosine | 0.7175（−0.67pp） | 0.8058（+6.3pp） | **1.0000** |
| maxlabel | 0.1981（崩溃） | 0.7763 | 1.0000 |
| gated cosine（CV 选 θ） | 0.7175 | 0.8055 | 0.9916 |
| gated maxlabel（CV 选 θ） | 0.2059 | 0.7754 | 0.9905 |

3. **coverage 的提升是"标签集合天然更大"的产物**：cosine 版本几乎 100% 都选多标签 meme（multi_rate≈1），严格命中反而 −0.67pp；maxlabel 更严重，strict 崩到 0.20（多标签 meme 的"任一标签命中"会压过 dominant 正确性）；
4. 门控（高置信只允许 one-hot）在 CV 里 θ 被 coverage 目标推到 0.9，等于"几乎不门控"，仍然没有 strict 收益。

**结论**：在当前数据与打分方式下，**"专门挑混淆性 meme + 多标签"不能提高严格指标**；只做"覆盖命中"会被多标签天然刷高，必须配合 multi_rate 与人工盲评才公平。因此**不加入演示页/默认匹配**，只作为负结论归档；`meme_emotion_multi.json` 保留为实验资产（默认不启用）。若未来继续，前提是：人工/AI 盲评 + 限制 multi_rate（如 <20%）+ 只在 pmax 很低的样本启用，而不是用 coverage 单指标选参。

产物：`结果\multi_label_match.md/.json`、`数据\meme_emotion_multi.json`、`代码\22_multi_label_match.py`。

8. **概率温度校准**开关（默认关，2026-11-02 落地）：勾选后用 T=0.65 缩放模型概率再做软匹配（T 在 val 上拟合，CV label_hit +0.50pp）；**只影响匹配打分**，不改变分类 argmax/准确率，页面概率条仍显示原始输出（详见 §6.8）。

### 7.3 局限

- **GIF 动图**：数据管线为保证训练/匹配/特征一致，`数据\meme_ready\` 里所有 meme 都是静态 256×256 PNG（GIF 只取首帧），所以模型输入、软匹配、视觉特征、神似模式仍然基于首帧；演示页的动图由独立脚本 `代码\16_meme_anim.py` 额外生成（`数据\meme_anim\`，**20 张** 256×256 压缩 GIF，合计约 **12.4 MB**），**只影响页面展示**；打开动图后首屏/切换时传输体积略大（单张 35 KB~1.2 MB）；
- **显存不足兜底（2026-11-01 起，2026-11-02 加固）**：演示页在视觉特征/神似模式前会 `empty_cache()`；若仍 OOM，会自动**降级 FER 特征 → ImageNet 特征 → CPU 计算 ImageNet 特征**并在页面提示，不再显示整块红色报错。2026-11-02 又加了 4 层防护：① **模型缓存上限**（`st.cache_resource(max_entries=2)`，切换权重/集成不再无限堆积旧模型）；② **"🧹 释放显存/内存缓存"按钮升级**：清 `st.cache_resource` + 释放 CLIP 状态（`sv.release_clip()`）+ 清特征与 ImageNet 模型缓存（`vd.release_feature_cache()`）+ `torch.cuda.empty_cache()` + `gc.collect()`，不删任何文件；③ **低显存自动 CPU 降级**：空闲显存 < 900MB 时神似模式的 CLIP 自动走 CPU（meme 特征有缓存，只需编码当前一张人脸，约 1~2 秒），ImageNet 视觉特征也自动走 CPU；即使 OOM 还会再用 CPU 重试一次；④ **OOM 提示更明确**（提示关闭 3-seed 集成/神似模式或占 GPU 的桌面程序）。实测视觉特征链路峰值显存约 **300 MB**（imgnet 211MB / fer 293MB）；2026-11-02 实测发现 8501 服务进程长期运行后自身显存堆积到约 **6.8 GB**（Windows 计数器口径），是"神似模式 OOM"的主因之一，用升级后的释放按钮/重启服务即可回收；
  > 说明：`KMP_DUPLICATE_LIB_OK=TRUE` **只用于屏蔽 OMP Error #15 的进程中止**（允许两份 Intel OpenMP 共存），它不释放/不限制内存或显存，**不能用来预防 CUDA OOM**；让两份 OpenMP 共存本身有稳定性风险，正确做法是统一 OpenMP 版本或按上述方式管理显存；
- 主流程不做自动人脸检测：上传图建议是"已经裁好的脸"，否则背景会干扰；**打开神似模式时**会用 `_deps` 里的 mediapipe 自动检测人脸关键点/裁脸（仅用于视觉打分，不改变模型输入）；
- meme 共 **66 张**（2026-11-02 扩库后；每类 ≥4），但情绪标签是人工看图标注，个别图（如 `lime-cat`、`side-eye-cat` 标为 disgust）存在主观性；神似模式的 meme 神态/气质标签同样是人工标注，主观性更强；
- 摄像头实时版未实现；
- 迁移学习模型依赖项目内 `_deps\`（timm + 预训练权重）；删掉后迁移模型推理/重训会失败，但自写 CNN 流程不受影响；
- **神似模式的附加依赖**：CLIP 权重 605 MB + mediapipe/opencv 等（`_deps` 总计约 934 MB）；缺依赖时神似模式开关自动隐藏，默认功能不受影响。

## 8. 结论与改进方向

### 8.1 结论

1. 完整管线可用：数据下载/预处理、Dataset、自写 CNN 与迁移学习、训练/评估、TTA、Streamlit 演示全部实跑通过；
2. 自写 CNN 最好到 **64.73% / 0.5368**；改用 **ImageNet 预训练 ResNet18 微调 + TTA** 后到 **69.71% / 0.6796**，超过 FER2013 常引用的人类水平（~65%）；
3. 数据不均衡（disgust 1.5%）是自写 CNN 的最大短板（完全放弃 disgust）；迁移学习把 disgust 召回从 0 提到 **60%**，说明"预训练特征 + 小数据微调"是解决小类问题的有效手段；
4. TTA 是低成本的稳定增益：不训练、不加参数，两个模型上都 +0.8~1.25 个点；
5. 软匹配 + 回退策略保证模型不确定或某类 meme 少时，演示仍然合理；
6. **建议 2 审查完成**：CLIP 整体视觉相似度没有跨域表情信号（P2 检索 0.160 vs 随机 0.163；P3 标签一致率 0.121 vs 门 0.40）→ 不做视觉融合主匹配；但 CLIP 文本属性画像（top-1 0.349，p=0.0015）与 478 点关键点几何带来可解释的"神态"信号，落地为**默认关闭的神似模式**（β 可调），验证集上情绪命中率几乎无损（-0.11pp）；
7. **模型优化 v2 完成**：配方升级（AMP/Lion/EMA/mixup/强增强/30 epoch）+ 更强 backbone（efficientnet_b0@160）+ 3-seed 集成 + TTA，把测试集从 **69.71% 提到 75.93% / Macro-F1 0.7443**（+6.22pp / +0.0647），其中 sad/fear/neutral/disgust 四类召回均明显提升；全程只用于选型的是验证集，测试集只评估一次。

### 8.2 改进方向

1. **多 seed 集成**：**v2 已落地**——3 个随机种子（42/43/44）概率平均，val +1.34pp、test +1.62pp；若想再稳可加到 5 seed（每个约 60 分钟）；
2. **更高输入分辨率 / 更长训练**：v2 已用 160 输入、30 epoch；可再试 192/224 输入、40 epoch（算力约 +50%~100%）；
3. **更强 backbone**：resnet50@128 因算力预算未跑；ConvNeXt/Swin/ViT 的 20 epoch 全量微调实测需 1.7~6 小时/个，需更强 GPU 或更长训练预算；
4. **针对 fear/sad 的不均衡处理**：v2 后 fear F1 0.6450、sad 0.6363 仍是最弱两类；**focal loss 已实测（§5.7，2026-11-02，单模型 No-Go，4 模型集成仅 +0.11pp）**；剩余可试：fear/sad 定向过采样、分层/粗粒度分类、阈值校准；
5. **人脸检测 + 对齐**：新建 Python 3.11 环境装 opencv，做摄像头实时版，并提升真实照片的演示效果（注：建议 2 的神似模式已用项目内 `_deps` 的 mediapipe 做关键点检测/自动裁脸，但仅用于视觉打分，主流程仍按原设计不依赖 opencv）；
6. **数据侧**：**FER+ 清洗标签已实测（§5.6，2026-11-02）**：按原始标签口径 **No-Go**（61.27% vs 72.61%），但在两套标签一致子集上 FER+ 模型 +3.1pp；说明继续提升应优先"重定义评估口径/人工盲评"而不是单纯换标签；以下方向仍可考虑：192/224 输入 + 40ep、更强 backbone（EffV2-B0/ConvNeXt-T）、drop_path/更强增强、k-fold 与伪标签；
7. **匹配层**：温度缩放已实测（§6.8，2026-11-02，label_hit CV +0.50pp、T≈0.65），推荐做成可选开关；情绪相似度矩阵调优在 CV 上仅 +0.27pp（全量 val +1.47pp 属过拟合），**不推荐**；
7. **神似模式的后续方向**：猫 meme 侧关键点（CatFLW）已验证照片风可行（36/58），若后续把插画/像素风筛掉或换更好的猫脸关键点模型，可把"猫侧关键点"也接入；视觉权重 β 与三路权重目前靠人工目检，可组织 20~30 人盲评做正式标定；CLIP 权重 605 MB 是否长期纳入交付可再权衡。
